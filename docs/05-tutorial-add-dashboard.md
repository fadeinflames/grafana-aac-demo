# 05. Туториал: добавляем дашборд

Дашборды удобнее **рисовать мышкой в UI**, а потом **положить получившийся JSON в Git**. Здесь главная ловушка — ссылка дашборда на источник данных. Разберём, как её не сломать.

## Почему ломается datasource

Каждая панель дашборда ссылается на датасорс. Ссылаться можно по имени (`"datasource": "Prometheus"`) или по `uid`. Имя можно переименовать, а `uid` у датасорса, созданного Terraform, **задан в коде** и всегда один и тот же: `prometheus-main` (см. `terraform/modules/datasource-prometheus`). Поэтому в JSON должно быть **только так**:

```json
"datasource": { "type": "prometheus", "uid": "prometheus-main" }
```

Ломают дашборд три типичные вещи:

1. Экспорт с галочкой **«Export for sharing externally»** — Grafana подставляет переменные вида `${DS_PROMETHEUS}` и блок `__inputs`. Terraform такие дашборды не умеет «подключать».
2. Дашборд нарисован на **другом** датасорсе (создан руками, у него другой `uid`).
3. Датасорс указан **именем** (старые дашборды).

От всех трёх защищает скрипт `scripts/validate_dashboards.py` (запускается в CI на каждый PR и командой `make validate`).

## Шаг 1. Нарисуйте дашборд в UI

> Рисовать лучше в **отдельной папке «Sandbox»**, созданной вручную. Terraform не знает о ней и не трогает её содержимое. В папках, которыми управляет Terraform (Demo, Infrastructure, Alerts), обычные пользователи (роли Editor/Viewer) могут только смотреть.

1. http://localhost:3000 → **Dashboards → New → New dashboard → Add visualization**.
2. В выборе источника данных — **Prometheus** (он появился после `make apply`).
3. В поле запроса (Code режим) введите, например: `sum(up)`. Выберите тип визуализации **Stat**. Заголовок панели: `Целей UP`.
4. **Save dashboard**, название `My Dashboard`, папка **Sandbox** (создайте кнопкой *New folder*).

## Шаг 2. Экспортируйте JSON (правильно!)

1. Откройте дашборд → кнопка **Export → Export as JSON** (в старых версиях: *Share → Export*).
2. **Не включайте** переключатель **«Export the dashboard to be used in another instance»** («для использования в другом экземпляре» / «Export for sharing externally»). Он должен быть **выключен**.
3. Нажмите **Copy to clipboard** или **Save to file**.

## Шаг 3. Положите JSON в репозиторий

Структура: `dashboards/<Папка в Grafana>/<имя-файла>.json`. Подкаталог = папка в Grafana. Для примера:

```
dashboards/
  Demo/
    my-dashboard.json     <- новый файл
```

В JSON должны быть:
* верхнеуровневое поле **`"uid"`** — стабильный идентификатор. Если в экспорте он есть — оставьте; нет — придумайте: латиница, цифры, дефис, до 40 символов (например, `"uid": "my-dashboard"`). Он определяет URL дашборда `/d/<uid>`;
* **`"title"`**;
* датасорс — только `{"type": "prometheus", "uid": "prometheus-main"}`.

Поля `"id"` и `"version"` можно оставить — Terraform их корректно обрабатывает (проверено: повторный `plan` чистый). Но `"id": null` аккуратнее.

> Новая папка в Grafana создаётся автоматически: достаточно создать новый подкаталог в `dashboards/`. Название подкаталога = название папки, и оно **не должно совпадать** с папкой, созданной руками, и с папкой `Alerts` (иначе Grafana ответит 409 — см. [08](08-troubleshooting.md)).

## Шаг 4. Проверьте локально

```bash
make validate
```
Должно появиться `✅ Дашборды в порядке: проверено файлов — 3` (было 2 + ваш).

Если в выводе есть `❌`, скрипт говорит точно, что не так:

```
❌ Найдены проблемы в дашбордах:

  - dashboards/Demo/broken.json: есть "__inputs"/"__requires" — это экспорт «для внешнего использования». Экспортируйте без этой галочки
  - dashboards/Demo/broken.json: panels[0].datasource: датасорс указан строкой "Prometheus". Нужен объект {"type": "prometheus", "uid": "prometheus-main"}
  - dashboards/Demo/broken.json: panels[1].datasource: uid датасорса — переменная "${DS_PROMETHEUS}". Замените на "prometheus-main"
  - dashboards/Demo/broken.json: panels[2].datasource: неизвестный uid датасорса "abc123". Допустимо: [...]
```
(Это реальный вывод на заведомо сломанном файле.) Исправляйте — поиском и заменой в редакторе.

Затем:
```bash
make plan
```
Ожидаемо: `# module.dashboards.grafana_dashboard.this["Demo/my-dashboard.json"] will be created` и `Plan: 1 to add`.

## Шаг 5. PR → merge → apply

Дальше всё как для алерта (см. [04](04-tutorial-add-alert.md), шаги 3–6): коммит, Pull Request, проверки, `terraform plan` в комментарии, merge, approve, apply. Локально — `make apply`.

После apply дашборд виден в **Dashboards → Demo**. Откройте его: панели должны показывать данные. Если в панелях ошибка `Datasource ... was not found` — в JSON неверный `uid` датасорса (см. таблицу выше).

## Шаг 6. Дальнейшие правки: как жить с UI после этого

Дашборд, созданный Terraform, **нельзя править в UI «навсегда»**: для обычных пользователей права папки — только просмотр, а правки администратора при следующем `apply` будут **затёрты** (и обнаружены как drift). Рабочий цикл такой:

1. Скопируйте дашборд («Save as») в вашу песочницу **Sandbox** и правьте там мышкой.
2. Экспортируйте JSON как в шаге 2, замените **содержимое** файла в `dashboards/…` (сохранив прежний `uid`!).
3. PR → merge → apply.

> Если оставить прежний `uid` и заменить JSON, дашборд обновится на месте — ссылки и закладки пользователей сохранятся. Если `uid` поменять, получится новый дашборд, а старый будет удалён.

## Шпаргалка: можно ли использовать переменные дашборда?

Да, переменные **внутри** дашборда (`templating.list`), например фильтр `instance`, работают как обычно. Нельзя только переменные-входы экспорта `${DS_...}` и `__inputs`.
